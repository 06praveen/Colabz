# Colabz — Phase 1 Backend & Database Learning Guide

Welcome to the **Phase 1 Learning Guide** for Colabz! This guide explains the core backend fundamentals you are learning and applying while building the Colabz MERN stack application.

## 1. Node.js Fundamentals

### What is Node.js?
Node.js is an open-source, cross-platform **JavaScript runtime environment** built on Google Chrome's **V8 JavaScript engine**. It allows JavaScript to execute outside a web browser directly on a server or computer operating system.

### Why do we use Node.js?
* **Single Language across the Stack**: Use JavaScript/TypeScript for both frontend (React/Vite) and backend (Express/Node.js).
* **Non-Blocking & Asynchronous I/O**: Node.js uses an event-driven, single-threaded event loop that handles thousands of concurrent requests efficiently without creating a new thread per request.
* **Massive Ecosystem (NPM)**: Access to millions of libraries and tools (Express, Mongoose, Socket.IO, Bcrypt, JWT, etc.).
* **Real-time Performance**: Perfectly suited for chat applications, live notifications, and real-time collaboration like Colabz.

### Node.js Runtime vs. Browser JavaScript
| Feature | Browser JavaScript | Node.js Runtime |
| :--- | :--- | :--- |
| **Environment** | Inside browser tabs (Chrome, Firefox, Safari) | Server, machine operating system |
| **Global Object** | `window`, `document` | `global`, `process` |
| **DOM & UI** | Can manipulate HTML, CSS, DOM events | No DOM or window object |
| **Filesystem & OS** | Restricted by sandbox security | Full access to filesystem (`fs`), OS (`os`), network (`http`, `net`) |
| **Module System** | ES Modules (`import/export`) | CommonJS (`require/module.exports`) and ES Modules |

## 2. Express.js Fundamentals

### What is Express?
Express is a minimal and flexible web application framework for Node.js that provides robust features for building single-page, multi-page, and hybrid web applications as well as RESTful APIs.

### Key Express Concepts:
1. **Server (`http.createServer` / `app.listen`)**:
   The engine listening on a designated port (e.g., `5000`) for incoming HTTP network connections.
2. **Route (`app.get`, `app.post`, `router.use`)**:
   Defines how an application responds to a client request at a particular endpoint (URI path) and HTTP method.
3. **Middleware (`app.use(fn)`)**:
   Functions that have access to the Request object (`req`), Response object (`res`), and the `next` middleware function in the application’s request-response cycle.
4. **Request (`req`)**:
   Contains information about the incoming HTTP request: `req.body`, `req.params`, `req.query`, `req.headers`, `req.user`.
5. **Response (`res`)**:
   Provides methods to send data back to the client: `res.status(200).json(...)`, `res.send()`, `res.setHeader()`.

## 3. MongoDB Fundamentals

### What is MongoDB?
MongoDB is a **NoSQL document database** designed for scalability, flexibility, and developer productivity. Instead of storing data in tables with fixed columns (like SQL), it stores data in flexible, JSON-like **BSON (Binary JSON)** documents.

### Key MongoDB Concepts:
* **Database**: A physical container for collections. In our app: `colabz`.
* **Collection**: A grouping of MongoDB documents (equivalent to a table in relational databases). Examples: `users`, `repositories`, `messages`.
* **Document**: A single record in a collection represented as key-value pairs (equivalent to a row in SQL).
* **ObjectId**: A unique 12-byte identifier (24 hex characters) automatically generated by MongoDB for every document (`_id`). It encodes:
  1. 4-byte timestamp of creation
  2. 5-byte random value unique to machine and process
  3. 3-byte incrementing counter

## 4. Mongoose Fundamentals

### What is Mongoose?
Mongoose is an **Object Data Modeling (ODM)** library for MongoDB and Node.js. It provides schema validation, business logic hooks, type casting, and relationship management.

### Key Mongoose Features:
* **Schema**: Defines the structure, types, default values, and validators of documents within a collection.
  ```javascript
  const userSchema = new mongoose.Schema({
    name: { type: String, required: true },
    email: { type: String, required: true, unique: true }
  }, { timestamps: true });
  ```
* **Model**: A compiled constructor from a schema that provides an interface to query, create, update, and delete database documents (e.g., `User.find()`, `User.create()`).
* **Document**: An individual instance of a Mongoose model with built-in helper methods (e.g., `user.save()`, `user.matchPassword()`).
* **Validation**: Built-in and custom checks ensuring data integrity before saving to MongoDB.
* **Indexes**: Specialized data structures that improve query execution speed (e.g., index on `email`, `owner`, `members`).
* **Populate**: Automatically replaces specified ObjectId references with the actual documents from referenced collections (simulating SQL joins).

## 5. REST API Concepts & HTTP Methods

A **REST (Representational State Transfer) API** is an architectural style for providing web standards-based communication between clients (like our React frontend) and servers (our Express backend).

### HTTP Methods:
* **`GET`**: Retrieve a resource or list of resources without modifying server state (Idempotent & Safe).
  * Example: `GET /api/repos` -> Fetches list of repositories.
* **`POST`**: Create a new resource or submit data for processing.
  * Example: `POST /api/auth/register` -> Creates a new user account.
* **`PUT`**: Replace an existing resource entirely.
  * Example: `PUT /api/repos/:id` -> Replaces all fields of a repository.
* **`PATCH`**: Partially update specific fields of an existing resource.
  * Example: `PATCH /api/repos/:id` -> Updates only the repository description.
* **`DELETE`**: Remove a resource from the database.
  * Example: `DELETE /api/repos/:id` -> Deletes the repository.

## 6. The Express Middleware Pipeline & Request Lifecycle

Middleware functions execute sequentially in the order they are registered in Express.

```text
Incoming HTTP Request (e.g., POST /api/repos)
  │
  ▼
[1] Security & Body Middleware (helmet, cors, express.json)
  │
  ▼
[2] Route Matcher (/api/repos)
  │
  ▼
[3] Custom Middleware (e.g., authMiddleware / protect)
  │   ├── Token valid? Attach req.user -> next()
  │   └── Token missing/invalid? -> Return 401 JSON immediately
  │
  ▼
[4] Controller Handler (createRepository)
  │   ├── Validate inputs
  │   ├── Query / Save to MongoDB via Mongoose
  │   └── Return standard JSON response (sendSuccess)
  │
  ▼
[5] Centralized Error Middleware (errorHandler)
      └── Catches any unhandled error or next(err) and formats response
```

## 7. Environment Variables & Security

* **`.env`**: A local plain text file containing environment-specific secrets, keys, and configurations (e.g., `PORT`, `MONGO_URI`, `JWT_SECRET`, `GEMINI_API_KEY`).
* **`process.env`**: The global Node.js object where `dotenv` loads these variables into runtime memory.
* **Why `.env` is never committed**:
  * Protects database passwords, API credentials, and cryptographic signing keys from being exposed publicly in Git repositories.
  * Allows different configurations across environments (development, staging, production).
* **`.env.example`**: A safe template committed to Git that lists required variable names with placeholder values so other developers know what variables to configure.

## 8. CORS (Cross-Origin Resource Sharing)

### Why does CORS exist?
Web browsers enforce the **Same-Origin Policy** for security. An origin is defined by the combination of **Protocol + Domain + Port** (`http://localhost:5173` vs `http://localhost:5000`).

Because Vite runs on port `5173` and Express runs on port `5000`, browser security blocks requests unless the backend explicitly authorizes requests from `http://localhost:5173` using CORS headers (`Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials`).

## 9. JSON Web Tokens (JWT) Conceptual Overview

A **JWT** is a compact, URL-safe means of securely transmitting claims between two parties.

### Anatomy of a JWT:
```text
Header.Payload.Signature
(e.g., eyJhbGci... . eyJpZCI... . SflKxwRJ...)
```
1. **Header**: Specifies token type (`JWT`) and signing algorithm (`HS256`).
2. **Payload**: Contains claims/data (e.g., `{ id: "user_123", email: "dev@colabz.io" }`, expiration `exp`).
3. **Signature**: Cryptographic hash created by hashing `Base64(Header) + "." + Base64(Payload)` with `process.env.JWT_SECRET`.

When a client makes a request, it includes the token in the `Authorization` header:
```http
Authorization: Bearer <token>
```
The server verifies the signature with its secret key without needing to query a session database on every request.

## 10. Centralized Error Handling

Instead of writing repetitive `try/catch` and error formatting in every route, Express allows centralized error handling:
1. When an error occurs or `next(err)` is called, Express skips normal middleware and jumps straight to the 4-parameter error middleware:
   ```javascript
   const errorHandler = (err, req, res, next) => {
     const statusCode = res.statusCode === 200 ? 500 : res.statusCode;
     res.status(statusCode).json({
       success: false,
       message: err.message || "Internal Server Error",
       ...(process.env.NODE_ENV === "development" && { stack: err.stack }),
     });
   };
   ```
2. In development, stack traces help developers locate bugs. In production, stack traces are hidden to protect server internals.

## 12. Technical Interview Questions & Answers

### Q1: What is Node.js?
**Answer**: Node.js is an asynchronous, event-driven JavaScript runtime environment built on Chrome's V8 engine that enables execution of JavaScript on the server.

### Q2: Why use Express over vanilla Node.js HTTP module?
**Answer**: Express simplifies server setup by providing built-in routing, middleware support, request/response helpers, body parsing, and template engine integration with minimal boilerplate.

### Q3: What is middleware in Express?
**Answer**: A middleware is a function with access to `req`, `res`, and `next`. It can execute code, modify request/response objects, terminate the request-response cycle, or pass control to the next middleware using `next()`.

### Q4: What is MongoDB and how does it store data?
**Answer**: MongoDB is a document-oriented NoSQL database that stores data in flexible, BSON (Binary JSON) documents grouped inside collections.

### Q5: What is the difference between SQL and MongoDB?
**Answer**: SQL databases are relational, table-based with strict schemas and SQL query language. MongoDB is non-relational, document-based with dynamic schemas and JSON-like query syntax.

### Q6: What is Mongoose?
**Answer**: Mongoose is an Object Data Modeling (ODM) library for MongoDB and Node.js that provides schema definition, data validation, middleware hooks, and type casting.

### Q7: What is an ObjectId in MongoDB?
**Answer**: A unique 12-byte BSON identifier automatically assigned to documents as `_id`, composed of a 4-byte timestamp, 5-byte process/machine identifier, and 3-byte incrementing counter.

### Q8: What is REST?
**Answer**: REST (Representational State Transfer) is an architectural style for distributed systems that uses standard HTTP methods, stateless communication, and resource-based URI endpoints.

### Q9: What is the difference between GET and POST?
**Answer**: `GET` retrieves data without modifying server state and sends parameters in the URL query string. `POST` submits data in the request body to create or process resources on the server.

### Q10: What is the difference between PUT and PATCH?
**Answer**: `PUT` completely replaces the target resource with the uploaded payload, whereas `PATCH` applies partial modifications to specific fields.

### Q11: What is CORS and why is it needed?
**Answer**: CORS (Cross-Origin Resource Sharing) is a browser security mechanism that uses HTTP headers to allow or restrict web applications running at one origin from requesting resources from a different origin.

### Q12: What are environment variables and why should `.env` not be committed?
**Answer**: Environment variables store configuration values outside application code. `.env` files contain sensitive secrets (database credentials, API keys) and environment-specific settings that must never be exposed publicly.

### Q13: What is a JWT and how does stateless authentication work?
**Answer**: A JSON Web Token is a digitally signed string containing a header, payload, and signature. Stateless authentication verifies the signature using a server secret on each request without saving session records in server memory or a database.

### Q14: Why must passwords always be hashed with salt?
**Answer**: Hashing is a one-way cryptographic function preventing plain-text exposure if a database is breached. A salt (random data added before hashing) ensures identical passwords produce distinct hashes, defending against rainbow table attacks.

### Q15: What is an index in MongoDB?
**Answer**: An index is a specialized data structure (typically a B-tree) that stores a small portion of the collection's data set in an easily traversable form, avoiding full collection scans and drastically speeding up queries.

### Q16: What happens when an API request reaches Express?
**Answer**: Express receives the HTTP request from Node's HTTP server, parses headers and body through registered global middlewares (CORS, body parser), matches the URI against the route table, executes route-specific middlewares and controllers, and returns an HTTP response through `res`.
